# Ergonet SEO Polish

Addon για CS-Cart 4.18 που διορθώνει τα ευρήματα SEO του Lighthouse **που τα γεννά ο
ίδιος ο πυρήνας** του CS-Cart, χωρίς επέμβαση σε core templates.

## Το εύρημα

Μετρήθηκε 02/09/2026 στο qualitytoners.gr, με τη λογική του
`lighthouse/core/audits/seo/crawlable-anchors.js`:

    crawlable-anchors  ✗  7 anchors σε σελίδα προϊόντος
                          3 σε κατηγορία · παρόμοια παντού

Ο πυρήνας γράφει `<a class="cm-submit" data-ca-dispatch=…>` **χωρίς href** για:
καρτέλες προϊόντος, +/− ποσότητας, dialog openers, και ένα κρυφό template stub
σελιδοποίησης με `href=""`.

**Ο έλεγχος είναι pass/fail.** Ένα anchor αρκεί για να πέσει ολόκληρος. Δεν υπάρχει
μερική βελτίωση.

## Η διόρθωση

Τα anchors αυτά **είναι κουμπιά** — δεν πλοηγούν πουθενά. Το `role="button"` είναι η
σωστή σημασιολογική δήλωση όταν δεν μπορείς να αλλάξεις το tag: το ίδιο πράγμα λέει
και στους αναγνώστες οθόνης. Το κρυφό stub παίρνει `role="presentation"`.

Ο έλεγχος `crawlable-anchors` παραλείπει ρητά anchors με μη-κενό `role` — άρα η
διόρθωση είναι ταυτόχρονα σωστή και αποτελεσματική, όχι τέχνασμα.

**Αποτέλεσμα:** 7 → **0** σε αρχική, κατηγορία, προϊόν, καλάθι.

## Γιατί output filter και όχι template overrides

Τα anchors βγαίνουν από **έξι** core templates. Έξι overrides στο παιδικό θέμα
σημαίνει έξι αντίγραφα που παγώνουν — κάθε διόρθωση που φέρνει μελλοντική αναβάθμιση
CS-Cart θα λείπει σιωπηλά από όλα. Ένα Smarty output filter, ένα σημείο συντήρησης.

**Γιατί όχι JavaScript:** το Lighthouse διαβάζει το DOM μετά την εκτέλεση, οπότε JS θα
«δούλευε». Αλλά τότε η προσβασιμότητα εξαρτάται από JavaScript — ακριβώς το αντίθετο
από το νόημά της.

## Τα μοτίβα είναι στενά κατά πρόθεση

Το `[^>]*` δεν μπορεί να περάσει έξω από το tag, και οι αρνητικές αναζητήσεις
(`(?![^>]*\shref=)`) ελέγχουν το **σύνολο** των attributes. Δοκιμασμένα απομονωμένα
σε 7 περιπτώσεις, μαζί με τις παγίδες: `<abbr>` και `<area>` δεν πιάνονται,
`data-x="a>b"` δεν σπάει το tag, anchors με υπάρχον `role` μένουν ανέπαφα.

Το stub της σελιδοποίησης απαιτεί **ΚΑΙ** κενό `href` **ΚΑΙ** `aria-hidden="true"` —
ένα anchor με κενό href που δεν είναι aria-hidden είναι πραγματικό σφάλμα και πρέπει
να παραμείνει ορατό στον έλεγχο, όχι να κρυφτεί από το φίλτρο.

## Προσοχή στη μέτρηση

Ένας αφελής έλεγχος «anchors χωρίς href» αναφέρει **29**· το Lighthouse μετρά **7**,
γιατί παραλείπει όσα έχουν `role`, `name` **ή** `id`. Τα 20 κουμπιά του καταλόγου
έχουν `id="button_wishlist_…"` και δεν μετρούσαν ποτέ.

Ο ίδιος αφελής έλεγχος ανέφερε και δύο αποτυχίες `link-text` που **δεν υπήρχαν**: το
SEO audit `link-text` ελέγχει **γενικό κείμενο** («κάντε κλικ εδώ»), όχι κενά links —
τα κενά είναι το `link-name` της κατηγορίας Accessibility.

Αν πας να μετρήσεις, υλοποίησε τη λογική του εργαλείου, όχι τη διαίσθησή σου.

## Εγκατάσταση

```bash
cp -r app/addons/ergonet_seo_polish <docroot>/app/addons/
php -r 'define("AREA","A");define("ACCOUNT_TYPE","admin");require "init.php";
        fn_install_addon("ergonet_seo_polish", true);'
```

Ρύθμιση `enabled` ως διακόπτης. CS-Cart 4.17+ · PHP 8.2+.
